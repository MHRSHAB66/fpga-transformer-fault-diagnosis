## 1. What is actually running and what is already complete?

### Takeaway
The board is occupied by an existing approximately eight-hour endurance run. Do not start an overlay load, golden check, UART sender, benchmark, dashboard, or another inference process until that run finishes. Most of the obvious paper experiments have already been done, including physical noisy-input comparisons; the useful next work is a small targeted evidence package rather than indiscriminate extra tests.

## 2. Which missing physical tests are worth doing before returning the board?

### Takeaway
Priority is: preserve/finish the current endurance evidence; obtain physical energy if equipment exists; test reproducibility after reload/boot and temporal-state transitions; close the noise-model timing gap with one short existing run. Transport stress is useful for engineering boundaries but should not be confused with novelty or allowed to redefine the proven deadline.

### Cited Findings
- Voltage and temperature are exposed, current/power/energy telemetry is absent in the documented board inspection; Vivado vectorless power is an **estimate**. Temperature and rail voltage alone cannot give measured W or J. Existing protocol specifies meter placement, idle / loaded-idle / active measurements, raw samples, integration and repetitions. — [Physical-power blocker and protocol](../../docs/reports/power_measurement_blocker_20261024.md), [Vivado estimates](../../docs/reports/paper_readiness_review_20261110.md)
- Vote history starts empty on bitstream load and persists across the continuous stream; k is clamped to 1..15 and ties choose the newest class. No reset API exists. Changing this would change the interface and needs a separately scoped decision. — [Reference contract](../../host/temporal_vote.py), [Driver](../../pynq/fault_classifier.py)
- Existing continuous fulltest has exact vote class/count at k=5 on 95,404 windows and 232 class transitions, median 2 and maximum 4 windows to correct vote. Per-recording 99.56% excludes first k-1 windows; continuous 99.084% includes them. These are different estimands. — [Paper review section 6](../../docs/reports/paper_readiness_review_20261110.md), [Vote checker](../../tools/raw_core_board_test.py)
- Existing hardware helper checks known active processes before launching, uses fresh versioned directories, uploads runner/guard, and runs under independent 75 C protection. The general guarded helper defaults to the older INT10-input deployment, so blindly using `{BIT}` there for raw-input tests would test the wrong overlay. — [Raw helper](../../tools/raw_core_board_test.py), [General guarded helper](../../tools/run_board_guarded.py)

- Cold boot should use a normal known-good boot and physical power action only after the current job ends and artifacts are fetched; no U-Boot/env/kernel modification is needed.
- Do not heat the device or inject supply faults to obtain thermal/voltage stress data. Natural steady-state temperature under existing guard is adequate for the described configuration; controlled ambient experiments would need actual equipment and scope.
- The transition experiment uses replayed recording changes, not a measured onset of a physical developing fault. A k-window vote can improve stability while delaying a true change; accuracy alone cannot characterize this tradeoff.
- The existing RT runner has no vote readout. Adding vote timestamp/readout for a new study must preserve old class timing fields and definition; otherwise comparisons become invalid.

### Gaps
- No automated cold-boot replay matrix, vote startup matrix, transport fault-injection harness, or real physical condition-transition dataset was found in the inspected scoped files. These are candidates for small work, not capabilities claimed already present.
- Physical sensor generalization requires sensor hardware/calibration and labeled measurements; prepared MAFAULDA replay cannot replace that. It is optional for the current project and need not block an implementation paper.

## 3. What can safely wait until the board is gone?

### Takeaway
Training, uncertainty analysis, literature positioning, and most ablations can be done after board return. Capture immutable hardware evidence now, and decide paper scope from the strongest reproducible result rather than trying to include every experiment.

### Cited Findings
- File-level bootstrap, stricter speed/severity splits, full C-model noise/dead-sensor sweeps, augmented-training regression, post-route reports and Vivado power estimates already exist. Highest-severity holdout is around 74% and must remain a reported limitation; the random-file split measures new recordings of known conditions. — [Current paper review sections 2–5](../../docs/reports/paper_readiness_review_20261110.md)
- FPGA vote and raw normalization are documented as part of the full raw-code-to-class path; the PC/ARM display confidence does not determine the class. — [Preprocessing report](../../docs/reports/onchip_preprocessing_20261109.md), [UART report](../../docs/reports/uart_result_path_20261109.md)

### Inferences
- Can wait: multi-seed training, robustness paired file-bootstrap, per-class/condition normal recall CIs, clean-noisy Pareto plots, temporal ROC/false-alarm/delay analysis of archived class streams, baseline comparisons, artifact manifests, report figures, and ablations against current retained checkpoints. New models or split changes remain explicit experimental variants and must preserve the approved deployment.
- Capture before return: exact bit/HWH/driver/source hashes and route reports per variant; raw inputs/reference outputs and class maps; timestamps tied to PC clock; board kernel/runtime identity; all timing raw arrays; temperature guard logs; UART bytes/PC receive traces; boot capture; measured meter traces if equipment exists; SD backup and short demonstration.
- Best defensible engineering claim is integration with measured correctness and timing under specified conditions. Measured energy and reproducible startup strengthen it. More hours of the same run alone add reliability evidence but do not create a new scientific contribution.

### Gaps
- Publication venue/novelty judgment requires primary-literature comparison; this board audit intentionally supplies hardware evidence and missing tests rather than declaring acceptance likelihood.
